# #618: REST schema and response cleanup for the notifications controller

- **URL:** https://github.com/WordPress/wp-feature-notifications/issues/618
- **State:** OPEN
- **Author:** @jonathanbossenger
- **Created:** 2026-10-16T08:36:46Z
- **Labels:** [Scope] Service, php

## Description

Part of #302. Blocks #176, #306 and #307.

### What problem does this address?

The REST schemas and responses don't support what the MVP client needs:

- `get_endpoint_args_for_item_schema( CREATABLE )` excludes every `readonly` property. Today `status` is readonly (so it can't be written, which blocks dismissing via #176) and `dismissed_at` is writable. Both are the wrong way round.
- No controller implements `prepare_item_for_response()`, so `_fields`, `context=embed`, `_links` and `register_rest_field` all do nothing.
- There are no `X-WP-Total` / `X-WP-TotalPages` headers, which the "N new notifications" header needs.
- There's no `after` param, which polling (#306) needs for delta queries.
- `icon` is typed `integer` but is a dashicon slug string. `channel` is `array of integer`, but channels have no integer IDs; they are namespaced strings.
- There are no `sanitize_callback` / `validate_callback` anywhere in the plugin.
- Every controller returns 401 for both logged-out and unauthorised requests.

### What is your proposed solution?

- Make `status` writable and `dismissed_at` readonly.
- Implement `prepare_item_for_response()` on the notification controller and add `X-WP-Total` / `X-WP-TotalPages` from `count_by_user()`.
- Add the `after` (`format: date-time`), `user_id` (default 0 = current user, gated on `manage_options`) and `include_expired` params.
- Make `icon` a string. Rename `channel` to `channel_name` with `'pattern' => '^[a-z0-9-]+/[a-z0-9-]+$'`.
- Add sanitize/validate callbacks; `accept_link` gets `'format' => 'uri'`.
- Return 401 when logged out and `rest_authorization_required_code()` (403) when logged in but not authorised.
- Register the item route with `WP_REST_Server::EDITABLE` (`POST, PUT, PATCH`), which satisfies both #176 and #376, plus `'allow_batch' => array( 'v1' => true )`.
- Keep `channel_title` in the *response* (derived from the registry) so `test_get_item_schema` still passes.
